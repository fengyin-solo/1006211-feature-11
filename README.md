# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 与
  `hydropower-plant-om:domain` 两个键，或在「运营概览」点「重置演示数据并重跑历史对齐」。

## 闸门归属、授权与跨页同步

闸门相关的业务规则集中在 `frontend/src/domain/`，通用台账仍走 `local-service.ts`：

| 文件 | 职责 |
| --- | --- |
| `domain/identity.ts` | 班组（运行甲班/运行乙班/检修班组/水情观测班）与可切换的值班身份 |
| `domain/ownership.ts` | 归属校验：启闭看责任班组或生效授权；故障/审批/改归属只认责任班组；观测岗只读 |
| `domain/gate-service.ts` | 闸门启闭、故障登记、归属变更、调班授权、操作留痕、孔数按闸段同步 |
| `domain/flood-service.ts` | 泄洪审批/开启/结束的归属拦截，与闸孔实测孔数对齐 |
| `domain/trashrack-service.ts` | 清污登记与拦污栅台账的跨页清污条数同步 |
| `domain/reconcile.ts` | 两套取值并存时以产生时间较晚的一套为准，统一另一侧并写对齐日志 |
| `domain/bootstrap.ts` | 历史数据按业务日期回填、缺项登记、存量取值一次性对齐（幂等） |
| `domain/lock.ts` | 同一时刻并发写入：同秒同业务键只保留一笔，后来者按重复拒绝 |
| `stores/notice.ts` | 提醒事项与待办清单，闸门/泄洪/拦污栅/概览页读同一份 |

规则口径：

- **归属**：每扇闸门登记责任班组与操作范围；只有本班组（或持有生效临时授权的借用班组）
  能发起开启/关闭，越权提交一律拒绝并返回写清归属冲突的话术；提交审批、登记故障、修改
  归属只允许责任班组；其他岗位（观测岗）只读孔口尺寸、启闭机信息与归属。
- **调班授权**：临时授权有开始/到期时间，到期自动收回；授权期间操作记录仍归原班组，
  记录同时保留实际操作班组与授权依据。
- **重复与并发**：同一扇闸门同一时段（一分钟）同方向重复操作只认第一条，后到的按重复
  拒绝；同一时刻（同一秒）并发写入只保留一笔。
- **孔数同步**：闸门开启后按闸段折算开启孔数，实时同步泄洪操作页；两套取值并存时以
  产生时间较晚的一套为准并统一另一侧，保证两页读到的孔数一致。
- **清污同步**：清污结果同步拦污栅台账，闸门页与拦污栅页读到的清污条数相同。
- **历史治理**：历史操作记录按操作时间回填；早期没有操作人的，按该闸门责任班组补记为
  「XX班组值守人员（历史补记）」；历史数据按业务日期补数，无法推算的字段（如孔口尺寸）
  不臆造，挂「待补录」并在闸门页「历史缺项」清单单独罗列。
- **提醒/待办**：故障闸门、待审批泄洪、授权临期/到期、待清理拦污栅、历史缺项自动生成
  提醒；人工待办持久化，顶栏与各页面徽标实时同步。

领域规则自带 46 项冒烟测试（越权、授权、重复、并发、回填、取值对齐、清污同步）：

```bash
cd frontend
npm run smoke
```
