# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries:v2` 与
  `hydropower-plant-om:domain:v1` 两项（旧版 `hydropower-plant-om:entries` 已废弃）。

## 闸门归属与操作权（班组口径）

闸门、泄洪、拦污栅三条线的规则收口在 `frontend/src/domain/`，页面不做业务判断：

- **归属到班组**：每扇闸门登记「责任班组」与「操作范围」（仅开启 / 开启+关闭 / 全开含故障登记）。
  只有责任班组，或持有该闸门**有效临时授权**的借权班组，能发起开启、关闭、登记故障。
  越权提交一律挡回，操作记录留痕并写清归属冲突（哪个班组动了归谁的闸门）。
- **提交审批、登记故障、改归属**同样仅责任班组可做；其他岗位对闸门只读，
  只能看闸门编号、孔口尺寸、启闭机型号等静态信息，看不到操作入口。
- **调班借权**：责任班组可向其他班组发放带起止时间的临时授权，到期自动收回（读取即判定，
  无需定时任务），责任班组也可提前收回。借权期间产生的操作记录，**归属仍记原责任班组**，
  实际操作人列标注「(借权)」。借权班组不能再转授权（只认责任班组发出的授权链）。
- **重复 / 并发**：同一扇闸门、同一动作在 5 分钟窗口内只认第一条受理，后到的按重复拒绝；
  同一时刻的并发提交由「每次从 localStorage 重读 + 业务键判重」保证只落一笔（单机 JS 线程串行，
  跨标签页靠存储重读）。清污登记同样适用。
- **开度 ↔ 泄洪孔数同口径**：闸门当前开度 > 0 即计 1 孔，按泄洪闸组汇总成「开启孔数」。
  泄洪页孔数与状态实时从闸门口径派生并回写，闸门开着泄洪票不可能算关闭；
  有闸门开着时禁止「结束泄洪」。
- **拦污栅台账同源**：清污条数由共享清污台账（append-only）派生，闸门页「关联清污条数」、
  概览页、拦污栅页读的是同一个数。
- **争议取值对齐**：两套取值并存且有争议时，以更新时间较晚的一套为准并统一回写，
  闸门页「立即对账统一取值」可手动触发，应用启动时自动执行一次；每次对齐在
  「历史补数 / 争议取值对齐 / 缺项清单」表里留痕。
- **历史数据补数**（既定决策）：操作台账按业务日期回填；早期没有操作人的记录，
  统一按闸门（或拦污栅）的责任班组补记，操作人写作「历史补记·XX班」并标注来源；
  无法从业务推断的事实字段（如 GATE-0006 的孔口尺寸）不臆造，置「待补」并在缺项清单单独罗列，
  由对应责任班组补录。
- **提醒/待办同步**：故障闸门、待清理拦污栅、待审批泄洪票、近 24 小时越权拦截、
  临期授权、缺项等待办由 `stores/notice.ts` 全局统一计算，概览/闸门/泄洪/拦污栅页
  引用同一个 `NoticePanel`，任意页面操作后同步刷新。

规则自检脚本：`node frontend/scripts/verify-rules.cjs`（不依赖浏览器，覆盖归属、
授权到期、操作范围、重复并发、孔数同步、清污同源、争议对齐、历史补数等 34 条断言）。
